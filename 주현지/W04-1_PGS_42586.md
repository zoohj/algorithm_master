### 1. 💡 핵심

* > **"뒤의 기능이 완료되어도 앞의 기능이 끝날 때까지 기다려야 한다 → 선입선출(FIFO)의 원리"**

* 각 기능의 '**남은 작업 일수**'를 먼저 계산하는 것이 핵심.
* 기준이 되는 앞선 기능보다 빨리 끝나는 기능들을 하나의 **배포 묶음(박스)**에 담다가, 더 오래 걸리는 기능을 만나는 순간 박스를 닫고 새 박스를 시작.

---

### 2. 주의 사항

* **올림 처리 (Ceil):** `(100 - 진도) / 속도`가 딱 떨어지지 않으면 하루가 더 필요.
  *  `math.ceil`을 사용하거나 `-( (progress - 100) // speed )`와 같은 식 사용.
* **기준점(target) 갱신:** 새로운 배포 묶음이 시작될 때, 기준일(`target_day`)을 현재 기능의 완료일로 업데이트.
* **마지막 묶음 처리:** 루프가 끝난 뒤, 아직 `answer`에 추가되지 않은 마지막 `count`를 반드시 `append` 해줘야 누락되지 않음.
* **데이터 순서:** 기능은 `progresses` 배열의 순서대로만 배포될 수 있으므로 배열의 순서를 흐트러뜨리면 안됨(정렬X).

---

### 3. 코드 설계 흐름

1. **일수 계산:** 각 기능이 100%가 되기까지 필요한 `days` 리스트를 계산.
2. **초기화:** 첫 번째 기능의 완료일을 `target_day`로 잡고, 첫 번째 기능을 포함하므로 `count = 0`으로 시작하여 루프 시작. 
3. **비교 및 누적:** 
   * 현재 기능(`day`) $\le$ 기준일(`target_day`) $\rightarrow$ 같은 날 배포 가능 (`count += 1`)
   * 현재 기능(`day`) $>$ 기준일(`target_day`) $\rightarrow$ 이전 묶음 배포 (`answer.append(count)`), 기준일 갱신, `count = 1` 초기화.

4. **마무리:** 포문 종료 후 남은 `count`를 결과 리스트에 추가.

---

### 4. ☁️ 최종 정답 코드

```python
import math

def solution(progresses, speeds):
    # 1. 각 기능의 완료 소요 일수 계산
    days = []
    for i in range(len(progresses)):
        # (남은 진도 / 속도)를 올림하여 필요한 일수 계산
        finish_day = math.ceil((100 - progresses[i]) / speeds[i])
        days.append(finish_day)
    
    answer = []
    # 2. 첫 번째 기능을 기준으로 배포 묶음 만들기
    target_day = days[0] # 현재 배포 묶음의 기준일
    count = 0            # 함께 배포될 기능 개수
    
    for day in days:
        if day <= target_day:
            # 3. 기준일보다 빨리 끝나거나 같은 날 끝나면 한 박스에 담기
            count += 1
        else:
            # 4. 기준보다 오래 걸리는 기능을 만나면? 
            # 지금까지 쌓인 박스를 배포(append)하고 새 기준 설정
            answer.append(count)
            target_day = day  # 새로운 박스의 기준일
            count = 1         # 새로운 박스의 첫 번째 기능 확보
            
    # 5. ⭐️ 루프가 끝나고 마지막으로 쌓여있던 박스까지 배포
    answer.append(count)
    
    return answer

```
