## [DFS/BFS] 프로그래머스 - 43165. 타겟 넘버

> **핵심 키워드:** *#DFS #BFS #재귀 #이진트리 #완전탐색*

https://school.programmers.co.kr/learn/courses/30/lessons/43165

### 1. 💡 핵심

* > **"각 숫자마다 '+' 혹은 '-'라는 두 갈래 길(Binary Choice)이 있다."**


* **상태 트리 탐색:** 모든 숫자에 대해 두 가지 선택지를 적용하면 총 $2^N$개의 경로가 생기며, 이 중 결과값이 `target`과 일치하는 경로의 개수를 찾는 문제.
* **완전 탐색 가능성:** 숫자의 개수가 최대 20개이므로 $2^{20} \approx 1,000,000$. 1초 내에 충분히 연산 가능한 범위이므로 DFS/BFS를 이용한 완전 탐색이 적합.

---

### 2. 주의 사항

* **종료 조건 설정:** 재귀 함수(DFS)를 사용할 때, 인덱스가 배열의 끝(`len(numbers)`)에 도달했을 때만 `target` 여부를 확인하고 종료해야 함.
* **재귀 깊이:** 파이썬은 기본 재귀 깊이 제한이 있으나, 이 문제는 깊이가 최대 20이므로 별도의 `sys.setrecursionlimit` 설정 없이도 안전하게 동작.
* **반환값 누적:** 외부 전역 변수를 쓰기보다 `dfs(left) + dfs(right)` 식으로 반환값을 직접 더해나가는 방식이 코드의 응집도를 높이고 실수를 줄여줌.
* **메모리 사용:** BFS로 풀 경우 각 단계마다 가능한 합계를 큐나 리스트에 저장하게 되는데, 숫자의 개수가 많아질수록 저장되는 상태값의 개수가 기하급수적으로 늘어날 수 있음을 인지해야 함.


#### + 🧸 Related concepts
- `DFS`: **'끝까지 가봐야 직성이 풀리는 탐색'**, 모든 경우를 확인해야 하고 숫자의 개수가 적을 때 사용
- 만약 숫자의 개수가 40개 이상으로 늘어난다면 'Meet-in-the-middle'이나 'DP' 같은 더 고차원적인 접근이 필요

---

### 3. 코드 설계 흐름

1. **함수 정의:** 현재 처리 중인 숫자의 위치(`index`)와 지금까지의 합계(`current_sum`)를 인자로 받는 DFS 함수를 설계.
2. **종료 조건:** `index == len(numbers)`인 경우, `current_sum`이 `target`과 같다면 1을 반환하여 한 가지 방법을 카운트하고, 아니면 0을 반환.
3. **재귀 호출:** 현재 인덱스의 숫자를 더하는 경우(`+`)와 빼는 경우(`-`) 두 가지 경로로 재귀 호출을 진행.
4. **결과 합산:** 두 재귀 호출의 결과(1 또는 0)를 모두 합쳐 상위 호출로 전달.

---

### 4. ☁️ 최종 정답 코드

```python
def solution(numbers, target):
    def dfs(index, current_sum):
        # 1. 모든 숫자를 다 사용했을 때 (Leaf Node 도달)
        if index == len(numbers):
            # 최종 합계가 타겟과 일치하면 1개 방법으로 인정, 아니면 0
            return 1 if current_sum == target else 0
        
        # 2. 현재 인덱스의 숫자를 더하는 경로와 빼는 경로를 각각 탐색
        # 각 경로에서 찾은 '방법의 수'를 더해서 반환함
        plus_case = dfs(index + 1, current_sum + numbers[index])
        minus_case = dfs(index + 1, current_sum - numbers[index])
        
        return plus_case + minus_case

    # 시작: 0번 인덱스부터, 합계는 0에서 출발
    return dfs(0, 0)

```
